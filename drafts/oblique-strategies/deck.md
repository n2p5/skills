# The Deck

Fifty-three original lateral-thinking cards for deeply technical work.
Each card is a move, not advice — draw one at random and apply it sideways
to whatever is stuck.

Inspired by *Oblique Strategies* by Brian Eno and Peter Schmidt (1975).
Every card below is original to this project; none reproduces their deck.
If these cards are useful to you, their actual deck is worth owning.

## Cards

- Put the hinge where it keeps breaking.
- Which warning became wallpaper?
- Delete the fix; let the bug speak again.
- Suppose the code is correct. What's broken now?
- Nothing may be configurable. Choose for them.
- It fails sometimes. What is it counting?
- Sketch the data alone. Delete the code that disagrees.
- What secretly depends on this staying slow?
- Promote the workaround. Demote the plan.
- Restart it. What remembered too much?
- Read your diff as the person who will delete it.
- Which name is a lie everyone agreed to?
- Strip every safeguard; watch what fails first.
- Both witnesses are telling the truth. Describe that world.
- Halve the interface. Which half do callers mourn?
- Read the production config as a confession.
- What happens in the first millisecond?
- Two modules share a secret. Make one forget.
- Your cache holds beliefs. Which are now false?
- Make the bug worse on purpose.
- Name the dependency that appears in no manifest.
- Reproduce your success like a bug.
- Deliver every message twice. Who pays twice?
- Watch it fail without reaching for the fix.
- Find the branch no one has ever taken. Walk it.
- Explain it without the word you keep using.
- Run it by hand until you and the machine disagree.
- Freeze the interface forever. Where does change go?
- What does the broken version do reliably?
- Make the edge case the only case.
- It broke last night and healed itself. Study the healing.
- Prove your prime suspect innocent.
- Swap who serves whom.
- Lie to the clock; see what believes it.
- Which test has never failed? Ask what it guards.
- Subtract until it breaks, then study the break.
- If the system documented itself, where would it lie?
- Turn off the cache. Is the truth fast enough?
- You inherited this from someone long dead. Honor or betray?
- What changed in everything you didn't change?
- Stare at one real record until it confesses.
- File the bug report your fix will cause.
- Restore from backup; meet what nobody saved.
- Find the bug's twin in your design.
- Treat your own module as a hostile vendor's.
- What can this system never verify about itself?
- Rename everything after what it actually does. Now read it.
- Delete the piece you'd fight to keep; watch what rushes in.
- Draw every arrow from memory. Chase the one you hesitated on.
- Which part exists to impress someone? Remove the audience.
- Run it single-threaded. What was the concurrency buying?
- Find the word doing two jobs. Fire it from one.
- Point your sharpest tool at itself.
